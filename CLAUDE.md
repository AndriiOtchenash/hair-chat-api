# hair-chat-api — CLAUDE.md

Backend for a hair-care chatbot (cosmetic advice, NOT medical). FastAPI + PostgreSQL/pgvector.
Sibling repos: `hair-chat-web` (React SPA), `hair-chat-infra` (docker-compose, Portkey config, fly.toml).
Owner background: senior-ish Java/Spring dev, new to Python and LLM apps — explain Python/LLM-specific
idioms briefly in PR descriptions when they differ from Spring conventions.

## Stack (do not change without an ADR in docs/adr/)
- Python 3.12, uv, FastAPI, Pydantic v2, pydantic-settings
- SQLAlchemy 2.0 async (asyncpg), Alembic, PostgreSQL 16 + pgvector
- httpx, openai SDK (used against OpenAI-compatible endpoints: Gemini, Groq; later Mistral,
  Bedrock, Portkey). openai SDK v3 runs on `httpx2`: provider code and its tests use httpx2 types.
- Provider chain from env `LLM_CHAIN` = `provider:model,...` in priority order (ADR 0002);
  every model must be listed in app/llm/registry.py with max_context_tokens. Default:
  gemini:gemini-3.8-flash,gemini:gemini-3.5-flash-lite,groq:openai/gpt-oss-120b.
  Prod needs a paid-tier GEMINI_API_KEY (free tier may train on prompts).
  Tests use FakeLLMProvider / FakeEmbedder (tests/llm_fakes.py) only.
- ENV = dev | staging | prod. staging behaves like prod (AUTH0_*, OPENAI_API_KEY, every
  LLM_CHAIN key and GEMINI_API_KEY required at startup, app.cli.chat refuses) but may set
  KB_INCLUDE_DRAFTS=true. Staging = Fly app hair-chat-api-stg (fly.toml), Flycast only, no
  public IPs (docs/deploy.md).
- DATABASE_URL may be a libpq URL (Neon): Settings normalizes it to postgresql+asyncpg with
  `ssl` from `sslmode`, other query parameters dropped; app and Alembic both read Settings.
- DB engine (app/db/session.py): asyncpg command/connect timeout DB_COMMAND_TIMEOUT_S (10),
  pool_recycle DB_POOL_RECYCLE_S (240), own ping on checkout instead of pool_pre_ping (that one
  lets a ping timeout reach the request): a dead or hung pooled connection invalidates the pool
  and the request runs on a fresh one (tests/integration/test_db_pool_recovery.py).
- Logging: `create_app()` calls `app.core.logging.configure_logging(LOG_LEVEL)` (default INFO):
  one stdout handler on the `app` logger, "%(levelname)s %(name)s: %(message)s",
  propagate=False, idempotent; uvicorn's loggers untouched. CLIs keep their own basicConfig.
  Tests check log output via capsys (pytest 9 caplog still sees non-propagating loggers).
- Dev environment: GitHub Codespaces via .devcontainer/ (Python 3.12, uv, Node LTS for Claude Code,
  docker-in-docker for testcontainers). The owner's local PC cannot run Docker — never assume it.
  The frontend lives next to this repo in /workspaces/hair-chat-web (cloned by postCreateCommand,
  codespace has write access to it) and has its own CLAUDE.md. Forwarded ports: 8000 API, 5173 web.
- Never call China-hosted APIs (DeepSeek, Zhipu, Moonshot, Qwen Singapore) with real user data.
- Auth: Auth0 JWT validated via JWKS; roles stored in our DB (user / specialist / admin)
- Background work: in-process only (no Celery/Redis). After a chat answer (summarizer, conversation
  index) use `app.core.background.BackgroundJobs.spawn`, never FastAPI BackgroundTasks: those run
  before yield-dependencies exit, i.e. while `start_reply` holds the generation slot, so the next
  message would be 409 until they end. Tests wait with `await live.jobs.join()`, no polling.
- Tests: pytest, pytest-asyncio, testcontainers (pgvector/pgvector image)
- Lint/types: ruff (lint + format), mypy --strict on app/

## DB conventions
- Models live in app/db/models.py on `app.db.base.Base`; PKs are UUID v7 from `new_id()`
  (ADR 0001), generated in the app — raw-SQL inserts must supply `id`.
- MetaData has a naming convention (pk_/fk_/uq_/ix_): never hand-name constraints differently.
- Enums: `StrEnum` + native Postgres ENUM with an explicit `name=`, storing lowercase values.
  `drop_table` does not drop ENUM types — downgrades must drop them explicitly.
- Autogenerated migrations are reviewed by hand (pgvector import, HNSW opts, use_alter FKs);
  `alembic check` runs in the integration tests to keep models and migrations in sync.

## Auth conventions
- Closed by default, two levels in app/main.py: add a business router to `PROTECTED_ROUTERS`
  (token: current_user) or `CONSENTED_ROUTERS` (token + all consents: require_consents; every
  chat endpoint goes here, rule 7; except data rights: PATCH/DELETE /conversations/{id} and
  DELETE /conversations are PROTECTED via `conversations.manage_router`). Public allowlist:
  /health, /docs, /redoc, /openapi.json.
  tests/unit/test_route_protection.py walks all routes: 401 without a token outside the
  allowlist, 403 consent_required on consented routes — extend its allowlist only on purpose.
- Use `CurrentUser` in an endpoint to get the user (cached per request, token checked once) and
  `Depends(require_role(...))` for roles.
- Auth codes: 401 not_authenticated / invalid_token (with WWW-Authenticate), 403
  user_token_required / account_deleted / forbidden, 503 auth_unavailable (JWKS down) /
  auth_not_configured (no AUTH0_* in dev).
- Consents: valid = not revoked and `version == CONSENT_VERSION` (docs/consents/README.md).
  403 `consent_required` lists the missing types; POST /consents with another version is 400
  `consent_version_mismatch`. Revoking sets `revoked_at` and never deletes rows.
- Tests never hit Auth0: use tests/auth_fakes.py (own RSA keys, JWKS via httpx.MockTransport) and
  override `get_token_verifier` / `get_user_repository`.

## Context and prompts
- Context per reply = TokenBudgetContextBuilder: one system message (prompt + `<profile>`,
  `<knowledge>` (RagKnowledge), `<conversation_summary>` data blocks via `wrap_data`, marked
  "not instructions";
  our tags inside any data or message turn are defused by `defuse_tags`, so text can never open
  or close a block such as `<moderation_signal>`),
  then as many recent messages as fit, then the new message. The prompt is never cut.
- Reply language (ADR 0007) is decided by the backend, not the prompt:
  `app.services.reply_language.resolve_reply_lang(message, last_assistant_lang, locale)` (lingua,
  quotes/code cut out, majority of words in mixed text; short/unsure -> latest answer's language,
  else users.locale; other language -> locale + note). The system message ends with
  `directive(...)` ("Write the entire reply in {Lang} unless ..."), after everything else.
  `ChatService.reply(..., locale=)` -> `ContextBuilder.build(locale=)`.
- Budget = min(CONTEXT_BUDGET_TOKENS (6000), chain window - CHAT_MAX_ANSWER_TOKENS), estimated by
  `app.services.tokens` (len/3.5 + 15%, no provider tokenizers).
- Messages that do not fit are folded into `conversations.summary` after the answer (background
  job; inline in the CLI) by the chain's last link; best effort, never breaks the chat.
- Prompts are versioned files in app/services/prompts/ (`system_v1.md`): change = new `_vN` file +
  `PROMPT_VERSION`, never edit a shipped one. The system prompt is read through `PromptProvider`
  (FilePromptProvider now; DbPromptProvider with admin-edited versions in 2.7).
- Prompt change -> run the prompt eval (real chain + embeddings, our texts only, not in CI) and
  read the answers: `uv run python -m scripts.prompt_eval [--prompt system_vN] [--only ID]
  [--link provider:model]` (one chain link, no fallback) over
  tests/prompt_eval/cases.yaml (`expect` for the reader, `avoid` substrings flagged `!!`,
  `kb_used: true|false` flags a tag that is missing / unexpected; `??` when a kb case got no
  passages, `kb_context:` shows them or the embeddings error). Cases may carry `history`,
  `summary` (conversations.summary) and `kb_slugs` (articles the search must find, `!!` if not).
  `locale` sets the interface language (default `lang`), `answer_lang` the expected reply
  language (default `lang`); each answer prints `reply_lang` (the backend's pick) and the
  detected language of the whole answer and of its first sentence, `!!` on a mismatch.
  Script check: a pl/en answer with any Cyrillic letter -> `!! cyrillic in latin-script answer`;
  a uk/ru answer with a 3+ letter Latin word outside quotes/code/parentheses and not in
  `LATIN_OK` (ok, pH, SPF) -> `?? latin word` (warning only).
  `--retrieval-only --query last|user3|summary|chat ...` = embeddings only, no LLM: kb_context
  per search-query variant (`chat`, the default = what the chat does). Eval vectors are cached
  in .cache/embeddings.json (git-ignored, key = sha256 of model+dimensions+text).
- The answer never mentions articles / the knowledge base: the client shows `done.sources`.
- No gendered forms about the assistant or the user in uk/ru/pl, one polite register (ru/uk
  «вы»/«ви», pl impersonal: no «ty», no Pan/Pani), system_v8+; eval group `gender`.

## Knowledge base / RAG (ADR 0005)
- Articles: docs/kb/<slug>.md, Russian, YAML frontmatter (title, language, status draft|reviewed,
  topics, sources, license, url?), format in docs/kb/README.md. Same text rules as the prompt.
- Ingest: `python -m app.rag.ingest docs/kb [--dry-run]`, idempotent: content_hash unchanged ->
  no embedding; changed -> chunks replaced; file gone -> document deleted. Chunks ~500 tokens
  along markdown headings, ~50 overlap, each starts with "Title › Section".
- Embeddings: EMBEDDING_MODEL (gemini-embedding-2, 768 = vector(768)), one model for the index;
  the search filters on `embedding_model`. No fallback: embeddings down (or > EMBEDDING_TIMEOUT_S)
  -> `QueryFailed(code)`, answer without `<knowledge>` + warning, and a `<knowledge_status>` note
  (KB_UNAVAILABLE_SIGNAL, never cut, in DATA_TAGS) tells the model to be more cautious and
  suggest a trichologist. The query is embedded in parallel with moderation.
- Every saved answer stores `messages.retrieval` JSONB `{status: ok|empty|error|disabled,
  passages, kb_used: [valid ids], error?}` (`chat_service.retrieval_record`; error = safe code
  only, never text; null = before the column / user messages). The answering link is
  messages.provider/model. Not in the export (operational, like tokens_in / llm_calls).
  `uv run python -m app.cli.rag_report [--days 7]`: shares per status, kb_used, per link.
- Search: top KB_TOP_K (4) by cosine distance, then KB_MIN_SIMILARITY (0.60), packed into
  KB_MAX_TOKENS (1500). Two searches from the second message on (one embeddings call): the
  latest message, and `dialog_query` = summary tail (<= 500 tokens) + latest message, else the
  last 3 user messages; `merge_hits` keeps the latest's best 2, then the dialog's, no duplicates
  (follow-ups keep the topic, a topic switch keeps the new one). Prod: reviewed only (prod refuses KB_INCLUDE_DRAFTS=true); dev: drafts too.
- Passages in `<knowledge>` are numbered `[1]..[n]`; the prompt (system_v6+) makes an answer
  that relies on them end with `<kb_used ids="1,3"/>`. `app.services.kb_used.KbUsedFilter` cuts
  the tag out of the stream (holds back a tail that may start it; never sent, never saved).
  `done.sources` = articles of the passages named in the tag (invalid / out-of-range ids
  ignored); no tag -> `[]`. `kb_used` is in DATA_TAGS, so no text can write one for the model.
  A prompt file may end with a part after `<!-- after knowledge -->`:
  `SystemPrompt.knowledge_reminder`, placed right after the `<knowledge>` block (only when the
  block is in the context).
- Threshold, model or articles change -> re-run the eval (real API, our texts only, not in CI):
  `uv run python -m scripts.rag_eval` over tests/rag_eval/queries.yaml (hit@4, false finds,
  threshold sweep; `known_gap` like moderation). Tests use FakeEmbedder (tests/llm_fakes.py).

## Conversation search (iteration 2 of 3: index + backfill + chat hook + API, format 3)
- `message_embeddings`: one row per answer (PK message_id, FK CASCADE to messages, plus
  denormalized user_id / conversation_id, both CASCADE and indexed), vector(768) +
  embedding_model + index_format. No HNSW: search is exact within one user_id (rule 5).
- Text (format 3, `CONVERSATION_INDEX_FORMAT_VERSION`) = gemini-embedding-2's asymmetric
  document format without a title: "title: none | text: Вопрос: <latest user message before
  the answer>\nОтвет: <answer>" (`index_text`), cut to CONVERSATION_INDEX_MAX_CHARS (16000;
  gemini-embedding-2 takes 8192 tokens and silently cuts the rest): question kept, the answer
  cut. No conversation title: in format 2 it filled short pairs, so "hallo" beat the real
  question in its conversation (search_probe --pairs, staging). The search embeds
  `query_text(q)` = "task: search result | query: q". Both live in
  app/rag/conversation_index.py (search_probe uses them too). Format change = new version:
  every row of another version (or NULL: before the column) is re-embedded by the next index
  run; the search does not filter on it.
- Small talk is not indexed: answer shorter than CONVERSATION_INDEX_MIN_ANSWER_CHARS (200,
  stripped; measured lengths in config.py). `pending` never returns such an answer unless it
  still has a row (older format, or a threshold raised since): the run deletes that row
  (`drop`) and counts `skipped_small_talk`. So skipped small talk is not read again by every
  backfill, and a threshold change heals the index both ways.
- Skipped too (read again by every run): no question before the answer, question moderation
  `action == "block"` (never saved today, a guard only), users without every valid consent
  (version == CONSENT_VERSION, like require_consents; `skipped_no_consent`): nothing of theirs
  goes to the embeddings API. Soft questions are indexed.
- `ConversationIndexer.run(user_id, conversation_id)` (background, `BackgroundJobs.spawn`)
  indexes what one conversation lacks, after `done` in `send_message`: chat embedder, whole
  run within EMBEDDING_TIMEOUT_S. Own session via `sql_message_embedding_repositories`.
  Failure = WARNING with conversation id + code, never raised; no embedder (dev) or a client
  disconnect = not indexed. The backfill picks those up. A rename (`PATCH
  /conversations/{id}`) does not touch the index.
- `uv run python -m app.cli.index_conversations [--dry-run] [--limit N]`: answers with no row,
  a row of another model or format, or a stale one, plus small talk's leftover rows (deleted);
  keyset batches of 100 (one embeddings call
  + one transaction each), ingest's timeout/retries; counts only in the output. Run it after
  every deploy that bumps the format. Not in the export (derived, like retrieval).
- `GET /conversations/search?q=&limit=` (CONSENTED; q 2..500 chars after strip, limit 1..20,
  default 10, else 422 validation_error): `{mode, items: [{conversation_id, title, message_id,
  snippet, created_at, score, mode}]}`, best hit per conversation. message_id / snippet /
  created_at are the user's question (snippet <= 200 chars). `semantic`: cosine distance <=
  CONVERSATION_SEARCH_MAX_DISTANCE (0.40) and score >= top1 - CONVERSATION_SEARCH_MAX_GAP
  (0.05), both provisional (staging numbers in config.py); user_id + embedding_model filtered,
  score = 1 - distance, best first. Embeddings down / too slow / no key -> `text`: ILIKE over
  the user's own role=user messages (% _ \ escaped), newest first, score null. Logs mode,
  count, ms; never q.
- `uv run python -m app.cli.search_probe USER_ID "q" ... [--top N] [--all-pairs | --pairs]`:
  read-only experiment, modes A (stored vectors) and B (pairs re-embedded now in the current
  format, without small talk), with the top1-top2 gap; `--pairs`: each conversation's best 3
  pairs (question[:40] | score); prints titles, questions and queries, operator's own data
  only.

## Moderation (ADR 0004)
- Every user message is checked by `Moderator` (OpenAI omni-moderation-latest, OPENAI_API_KEY,
  3 s timeout, no retries) in `ChatService.reply` after the 404/409 checks, before it is saved.
- Policy = `app.services.moderation_policy.decide` (shared with the eval script):
  self-harm* -> soft (saved, answered; `<moderation_signal>` block after the system prompt,
  SSE `safety_notice` before the first token; wins over other categories);
  violence(/graphic) -> block only at score >= MODERATION_VIOLENCE_THRESHOLD (0.9);
  any other flagged -> block = 422 `message_blocked`, never saved; else allow.
- Log only the action and categories (no text, no scores, no user_id).
- Fail-open: moderation down (timeout, 429, 5xx, network; 4xx too but logged as error) ->
  the message goes through. `messages.moderation` = `{provider, model, flagged, action,
  categories?}`, `{status: "unavailable"}` or `{status: "disabled"}` (no key, dev only).
  Never store scores.
- Tests use FakeModerator (tests/llm_fakes.py); prod refuses to start without OPENAI_API_KEY.
- Policy or threshold change -> re-run the eval (real API, our phrases only, not in CI):
  `uv run python -m scripts.moderation_eval` over tests/moderation_eval/phrases.yaml.
  Accepted misses carry `known_gap: "<reason>"` (ADR 0004 Known gaps); only new ones exit 1.

## Data rights (ADR 0006)
- `GET /me/export` (JSON attachment) and `DELETE /me` `{"confirm": "DELETE"}` (204, else 422)
  are PROTECTED, not consented: they work after consents are revoked.
- Own conversations: `DELETE /conversations/{id}` (204), `DELETE /conversations`
  `{"confirm": "DELETE_ALL"}` (204, else 422), `PATCH /conversations/{id}` `{title}` (strip,
  1..120); PROTECTED, hard delete by cascade (messages -> linked llm_calls). 404 for someone
  else's; 409 conversation_busy while an answer is generated (delete all: any busy -> nothing
  deleted). A title set by the user is never replaced by the first-message auto-title.
- Delete = hard `DELETE FROM users`, everything else goes by `ON DELETE CASCADE` (new user
  data tables must cascade from users or conversations, and appear in the export). Then Auth0
  via Management API in a background task (AUTH0_MGMT_CLIENT_ID/SECRET): not configured ->
  warning, failed -> error log with user_id + auth_sub; our deletion is never rolled back.
- Retention: `python -m app.cli.retention [--dry-run]`, conversations with last_message_at
  older than RETENTION_DAYS (30) plus unlinked llm_calls as old; batches with
  `FOR UPDATE SKIP LOCKED`, counts only in the output. No HTTP endpoint. Daily scheduled Fly
  machine, docs/deploy.md.

## Error format (REST and SSE)
- Every error body is `{"code": "...", "message": "..."}` (`app.core.errors.ErrorBody`), no
  `detail` wrapper. Raise `api_error(status, code, message)`; a plain HTTPException gets a code
  from its status (404 -> not_found). Validation -> 422 `validation_error` with a short
  "loc: reason" summary that never echoes input values.
- The SSE `error` event carries the same ErrorBody as its data.

## Non-negotiable rules
1. No test calls a real LLM, embedding or moderation API. Use FakeLLMProvider / FakeEmbedder with
   scripted scenarios (success, fail-before-first-token, fail-mid-stream, timeout).
2. LLM providers are stateless. Never use provider-side conversation state (stored responses,
   interactions/session APIs, context caching). Full context is rebuilt from the DB on every call.
3. Token budget = min(max_context_tokens) across the fallback chain.
4. One embedding model for the whole index; every vector row stores `embedding_model`.
5. Every query on messages/profile/conversations filters by `user_id` of the current user.
   A missing filter is a security bug.
6. Never log message content or profile facts. Log ids, token counts, provider, latency.
7. Endpoints that touch chat return 403 `consent_required` until consents (18+, health data, AI) exist.
8. System prompt forbids diagnoses, dosages and treatment plans; escalate to a trichologist/doctor.
9. Tests assert behaviour through public interfaces, not implementation details.
   Coverage gate 80% on app/services, app/llm, app/rag.
10. Secrets only via env (see .env.example). Never commit keys.

## SSE contract (POST /conversations/{id}/messages)
event: safety_notice data: {"kind": "self_harm"}  # optional, first; client shows help lines
event: token    data: {"text": "..."}
event: restart  data: {"reason": "..."}    # provider failed mid-stream; client clears partial answer
event: done     data: {"message_id": "...", "provider": "...", "model": "...", "truncated": false,
                      "sources": [{"title": "...", "slug": "...", "url": null}]}
event: error    data: {"code": "...", "message": "..."}   # same ErrorBody as REST errors
: ping                                     # keep-alive comment every 15 s while idle (FastAPI)
- truncated = the answer hit max_tokens (finish_reason "length"); it is still saved.
- sources = knowledge-base articles the answer used, per its `<kb_used>` tag (may be empty;
  always present, the client hides an empty list).
- error codes: llm_unavailable (all providers down), llm_request_rejected (provider 400; not
  Gemini's bad-key / unsupported-location 400s, which fall back like 401/403:
  `app.llm.base.provider_side_400`), internal_error. The user's message is kept in every case.
- safety_notice comes at most once, before any token/restart/done/error, when moderation
  marked the message soft (ADR 0004).
- 404 not_found (missing or someone else's conversation), 409 conversation_busy, 422
  validation_error / message_blocked come as normal HTTP responses before the stream starts
  (checked in the `start_reply` dependency).
- Only a complete answer is saved (on done); a client disconnect cancels the generation and
  saves nothing. One generation per conversation, in-memory per process (ADR 0003).
- Test SSE against a live uvicorn (tests/integration/test_chat_sse.py): httpx's ASGITransport
  buffers the whole response.
